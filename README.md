# 报关三方资料差异核对小系统

供应商、货代、仓库三方报关资料（**品名 / 数量 / 箱单号**）按字段自动比对，标出差异；
负责人可认领、补件、重新核对、标记解决；**所有改动留痕**。
资料版本更新与重复提交复用同一条差异，不会生成两条。

第二期新增：**报关截止时间 + 临近/超时两级提醒与升级**（独立服务，故障不影响主流程，同轮风险不刷屏）；
**供应商受限补件入口**（带令牌的专用页面，只能补指定货的指定字段，看不到货代/仓库数据，
提交后自动挂回差异并重核，重复提交不多出版本）。

第三期新增：**申报包冻结与导出**——申报前把当时采用的三方资料版本和差异处理结论固化为
不可变快照（带来源、版本、提交人、时间），冻结后再来新版本也改不动旧包。

第四期新增：**判定—豁免—到期重开同一条流程**——关务可为一票货的字段维护**带版本的容差规则**
（数量绝对差/百分比、品名箱单号别名组，append-only），重核时保留原始三方值、命中的规则版本
与偏差依据，容差内按规则指定来源取值；对仍不满足规则的差异可申请**限时豁免**（原因、操作人、
到期时间必填），豁免期不催办；**到期 / 撤销 / 资料升版**后若仍冲突，复用原差异行开启新 episode
并恢复提醒。冻结时把当时的规则版本链与豁免证据固化进申报包，后来的配置改不动旧包；
历史上没配过规则的货票继续严格比对。

## 运行

```bash
pip install -r requirements.txt        # 仅需 Flask（Python 3.10+）
python3 app.py                         # Web：http://localhost:5000
python3 reminders.py --loop --interval 60   # 提醒/升级服务（独立进程，也可 cron 每分钟调 --once）
# 超时升级联系人可配置（默认“关务主管”），通知规则不变（临近给负责人/未认领兜底给主管；超时给负责人+主管）：
python3 reminders.py --once --escalation-target "值班主管周"
ESCALATION_TARGET="值班主管周" python3 reminders.py --loop
```

- SQLite 数据库自动建在 `data/customs.db`（可用环境变量 `CUSTOMS_DB` 覆盖）。
- 通知渠道在 `reminders.py` 的 `Notifier` 接口替换（现默认打印到控制台，模拟企业微信/邮件）。

## 业务流程

1. **建票**：一票货一个编号（`shipment.ref` 唯一），可同时设置报关截止时间与提前提醒小时数。
2. **录入三方资料**：每方每个字段一行版本化记录（`document`，来源唯一）。
   - 三方内容与现行版本完全相同 → 判定**重复提交，忽略**（不升版本、不重算）。
   - 有字段变化 → 版本 +1，自动重新比对。
3. **自动比对（判定链：严格 → 容差 → 差异）**：
   - 品名、箱单号：忽略空格/大小写；数量：忽略千分位、小数尾零（`1,000` = `1000.00`）。
   - 仅一方提交不算差异；≥2 方归一化后不一致才算严格冲突。
   - 该字段**配过容差规则**时，继续判定偏差是否落在允许范围：数量支持绝对差（±N）或
     百分比（±N%，按最大/最小/平均值），文本支持别名组；命中即按容差视为核对一致，
     申报采用值取规则指定的一方。**从未配过规则的字段/历史货票永远严格比对。**
4. **容差规则（带版本）**：一票货一个字段一条版本链，`tolerance_rule` append-only：
   - 维护规则 = 新增版本（旧版置 `superseded`），停用 = 现行版置 `revoked`，版本与配置都保留。
   - 发布/停用后自动整票重核。收紧规则使原容差内差异重新暴露时，**复用原差异行、episode+1**；
     放宽规则则重新容差通过，并把差异上的规则版本/依据刷新为新版本。
   - 每次判定都在差异行固化 `rule_version`、命中依据（模式、参数、基准、实际偏差、采用来源），
     原始三方值（`values_json`）始终原样保留，不做任何抹平。
5. **差异处理**：待认领 → 认领（负责人）→ 补件（说明追加留痕）→ 资料更新后**重新核对**
   （提交时自动触发，也可手动整票重核）→ 一致（严格或容差内）后差异变为「核对一致，待确认」→ 负责人确认解决。
   - 未核对一致（含超出容差）不能标记解决。
   - 已解决/已核对一致的差异若在新版本中再次冲突，**同一行重新打开**（`episode + 1`），绝不新增第二条。
6. **限时豁免（例外放行）**：对仍不满足规则的差异可申请豁免，**原因、操作人、到期时间三者必填**：
   - 豁免授予时把当时三方值、规则版本写入 `waiver.basis_json`；该差异已排队/失败待重试的通知
     立即置 `cancelled`，豁免期内提醒服务完全静默（临近与超时都不催）。
   - 三种终结方式，全部复用原差异行：
     - **到期**：提醒服务每轮扫描先惰性到期（Web 详情页加载时也会处理，幂等），仍冲突 →
       episode+1 并在**同一轮扫描**恢复提醒；
     - **人工撤销**：立即重开（仍冲突时 episode+1）；
     - **资料升版**：提交涉及该字段时豁免自动终结——仍冲突则 episode+1 恢复提醒，
       改齐/落入容差则置 `superseded` 不开新轮。重复提交（未升版）与不相关字段变更不动豁免。
7. **提醒与升级**：
   - 进入 `deadline - warn_hours` 窗口后，每条未解决、未核对一致且**不在豁免期内**的差异提醒一次
     负责人（未认领则提醒关务主管）；超过截止时间后**升级**通知关务主管。豁免中的差异完全静默。
   - **不刷屏**：`reminder_event` 对 `(差异, 级别, episode)` 建唯一约束，同一风险轮次反复扫描
     只会拦截；差异解决后再次冲突、或豁免到期/撤销/资料升版后重开（新 episode）才允许再提醒一次。
   - **故障隔离**：提醒服务只写 `reminder_event/notification/audit_log`，通知发送失败记
     `notification.status=failed` 并在后续扫描自动重试；提醒服务宕机期间 Web 录单、认领、
     补件、重核全部照常。
8. **供应商补件门户**：
   - 内部在货票页勾选字段、设置联系人后生成一次性令牌链接（默认 72h 有效，可吊销）。
   - 供应商打开 `/portal/<token>`：**只能看到本方资料与被授权字段的核实状态**，
     页面不包含货代/仓库的任何数据，也没有内部导航。
   - 提交只允许写令牌白名单字段（篡改表单加入其他字段 → 403 拒绝并留痕）；
     提交后自动挂回对应差异并触发整票重核（涉及豁免字段时同样按"资料升版"终结豁免）；
     内容没变重复点提交不产生新版本。
9. **申报包冻结与导出**：
   - 每个字段记录冻结时三方各自的值、版本号、提交人与提交时间；严格一致或容差命中才自动给出
     "采用值"（容差命中时注明规则版本、命中依据与采用来源）。
   - **冻结当时的容差规则版本链**（含被取代/停用版本）与**豁免证据**（原因、操作人、到期、
     批准时三方值、终结状态）随包固化；**豁免中的差异不算未解决，可直接冻结**（风险提示中列明）。
   - 差异结论随包固化：状态、轮次、负责人、补件记录、该差异从发现到解决的完整处理留痕。
   - **默认阻止带未解决差异冻结**（避免误申报）；确需带差异申报时勾选确认，风险提示和确认人会写入包内与日志。
   - 导出 **Markdown 申报核对单**（人读，适合打印/发邮件）或 **JSON 原始快照**（机读、可校验），
     每页/文件都注明包号、冻结时间、冻结人。
   - **不可变性**：快照整体存 `declaration_package.payload_json`，代码中没有也不需要任何
     UPDATE/DELETE 路径——后续升版、再冲突、再解决、规则改写、豁免撤销都只作用于活数据；
     需要新依据时再冻下一个包，多包并存、序号递增。
10. **留痕**：建票/截止时间、提交/更新/重复忽略、差异发现/更新/重开/核对一致/容差命中、
    规则版本发布/停用、豁免批准/到期/撤销/资料升版终结、认领、补件、
    令牌签发/吊销/越权拒绝/门户提交、提醒升级、通知投递状态（含豁免撤销）、
    **申报包冻结（含带差异确认、豁免中冻结）**，全部写入 `audit_log`。

## 幂等设计（核心约束）

`discrepancy` 表对 `(shipment_id, field)` 建唯一约束，比对引擎对差异一律 **upsert**：

| 场景 | 行为 |
|---|---|
| 重复提交相同资料（内部或门户） | 忽略，版本不变，无任何差异/豁免变化 |
| 新版本但冲突依旧 | 原差异行更新快照/版本，id 不变 |
| 新版本改齐 | 原行置 `is_reconciled=1` 并刷新快照，不删除、不新建 |
| 严格不一致但命中容差规则 | 不产生/重开差异；已有差异行置核对一致，固化 `rule_version`+偏差依据，原始值保留 |
| 规则收紧/停用导致超差 | 原容差内差异复用原行重开、`episode+1`、清空命中依据 |
| 豁免到期 / 撤销 / 资料升版后仍冲突 | 豁免终结，**复用原差异行** `episode+1`，恢复催办 |
| 豁免期间资料改齐/落入容差 | 豁免置 `superseded`，不开新 episode，差异正常走核对一致 |
| 解决/核对一致后又冲突 | 原行重新打开、清空负责人、`episode+1`（开启新一轮提醒） |
| 同轮风险重复扫描 | `UNIQUE(discrepancy,level,episode)` 拦截，不重复通知；豁免期直接静默 |
| 冻结后改规则/改资料/撤豁免 | 只写活数据；已冻申报包的 JSON 快照（含规则与豁免证据）永不更新 |

## 文件结构

| 文件 | 说明 |
|---|---|
| `core.py` | 建表/迁移、比对+容差判定、规则版本链、豁免状态机、差异 upsert(episode)、认领/补件/解决、截止时间、补件令牌、申报包冻结/导出 |
| `app.py` | Flask 路由：内部页面、规则维护、豁免申请/撤销、`/portal/<token>` 供应商入口、申报包下载（.md/.json） |
| `reminders.py` | 独立提醒/升级服务：风险判定（豁免期静默）、豁免惰性到期重开、事件幂等、通知投递与失败重试，`--once/--loop` |
| `templates/` | 列表页、详情页（截止时间/容差规则/豁免/升级记录/链接管理/申报包）、门户页、链接错误页 |
| `demo.py` / `demo2.py` / `demo3.py` / `demo4.py` | 四期完整业务流程演示 |
| `test_core.py` | 比对、容差规则版本化、豁免生命周期时序、幂等、提醒、门户、申报包的单元测试与 HTTP 冒烟 |
