# 报关三方资料差异核对小系统

供应商、货代、仓库三方报关资料（**品名 / 数量 / 箱单号**）按字段自动比对，标出差异；
负责人可认领、补件、重新核对、标记解决；**所有改动留痕**。
资料版本更新与重复提交复用同一条差异，不会生成两条。

## 运行

```bash
pip install -r requirements.txt        # 仅需 Flask（Python 3.10+）
python3 app.py                         # 打开 http://localhost:5000
```

- SQLite 数据库自动建在 `data/customs.db`（可用环境变量 `CUSTOMS_DB` 覆盖）。

## 演示与测试

```bash
python3 demo.py                        # 端到端演示：两处冲突→认领→重复提交→补件→重核→解决
python3 -m unittest test_core -v       # 11 个单元/HTTP 冒烟测试
```

## 业务流程

1. **建票**：一票货一个编号（`shipment.ref` 唯一）。
2. **录入三方资料**：每方每个字段一行版本化记录（`document`，来源唯一）。
   - 三方内容与现行版本完全相同 → 判定**重复提交，忽略**（不升版本、不重算）。
   - 有字段变化 → 版本 +1，自动重新比对。
3. **自动比对**：
   - 品名、箱单号：忽略空格/大小写；数量：忽略千分位、小数尾零（`1,000` = `1000.00`）。
   - 仅一方提交不算差异；≥2 方归一化后不一致才产生差异。
4. **差异处理**：待认领 → 认领（负责人）→ 补件（说明追加留痕）→ 资料更新后**重新核对**
   （提交时自动触发，也可手动整票重核）→ 三方一致后差异变为「核对一致，待确认」→ 负责人确认解决。
   - 未核对一致不能标记解决。
   - 已解决的差异若在新版本中再次冲突，**同一行重新打开**并退回待认领，绝不新增第二条。
5. **留痕**：建票、提交/更新/重复忽略、差异发现/更新/重开/核对一致、认领、补件、解决，全部写入 `audit_log`。

## 幂等设计（核心约束）

`discrepancy` 表对 `(shipment_id, field)` 建唯一约束，比对引擎对差异一律 **upsert**：

| 场景 | 行为 |
|---|---|
| 重复提交相同资料 | 忽略，版本不变，无任何差异变化 |
| 新版本但冲突依旧 | 原差异行更新快照/版本，id 不变 |
| 新版本改齐 | 原行置 `is_reconciled=1`，不删除、不新建 |
| 解决后又冲突 | 原行 `status` 回到 `open`、清空负责人 |

## 文件结构

| 文件 | 说明 |
|---|---|
| `core.py` | SQLite 建表、归一化比对、差异 upsert、认领/补件/重核/解决、审计日志 |
| `app.py` | Flask 路由（建票、资料录入、差异操作） |
| `templates/` | 列表页 + 一票货详情页（三方对照表、差异卡片、留痕时间线） |
| `demo.py` | 可运行的完整业务流程演示 |
| `test_core.py` | 核心逻辑幂等性与 HTTP 冒烟测试 |
